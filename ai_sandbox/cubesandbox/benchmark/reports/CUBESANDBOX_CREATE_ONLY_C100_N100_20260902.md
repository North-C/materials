# CubeSandbox create-only c100/n100 测试记录（2026-09-02）

## 结论

三轮 `cube-bench create-only` 测试分别完成 100/100 次创建，合计成功 300/300，
三轮均未报告错误。三轮吞吐依次为 255.98、246.32、252.28 sandboxes/s，CREATE
平均延迟依次为 164.1、175.2、166.5 ms，P99 依次为 229.7、240.9、230.1 ms。

这是三次成功的高并发创建观测，但当前证据只有终端汇总输出，缺少原始 JSON、逐请求日志、
Template 资源与镜像身份、测试前后资源计数、清理和 cooldown 记录。因此该结果不能单独作为
跨版本性能对比、完整生命周期性能或可重复性验收结论。

## 结果边界

### 已验证事实

- 三轮 `cube-bench` 均报告 100 个正式请求全部完成且错误数为 0，合计 300/300。
- 工具分别报告吞吐 255.98、246.32 和 252.28 sandboxes/s，以及上述 CREATE 延迟统计。
- 三轮终端分布各有 12 个区间，各自合计 100 个样本。

### 合理解读

- 在该 Template、该 API 端点和这三次运行条件下，100 并发的创建请求均没有出现工具可见失败。
- Run 2 的延迟高于 Run 1，而 Run 3 回到接近 Run 1 的水平；三轮汇总数据仍不足以判断统计显著性或稳定趋势。

### 尚不能确认

- `create-only` 结果不证明 Sandbox 已完成业务 readiness、guest 内命令执行或网络可用。
- 三轮都没有 DELETE 样本，不能推导删除、Rollback、Clone、Pause/Resume 或完整生命周期性能。
- 没有清理、冷却和完整环境身份，不能与其它日期、机器、内核或 CubeSandbox 版本直接比较。
- 工具给出的 `B` 是内置评分，不应在缺少评分规则和验收阈值时替代正式结论。
