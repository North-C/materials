# EPYC 9654：当前持续运行版本的 c100 复测与瓶颈抓取

日期：2026-10-29，北京时间。测试与收尾身份检查窗口 **17:27–17:34**。状态：**15 轮完成，1500/1500 正式请求成功，45/45 预热请求单独记录；五轮日志 profiler 抓取完成。** 本报告记录当时快照，不声明主机当前实时状态。

## 结论

当前持续运行版本的五轮普通前测整轮中位 **130.501 ms**，范围 **124.035–144.056 ms**，通过预先记录的诊断筛选，随后进行了五对采集/普通交错测试。普通对照 D 中位 **129.468 ms**，采集 F 中位 **132.245 ms**，组中位差 **+2.777 ms（+2.145%）**；配对均值差 **+2.752 ms**，范围 **−1.651～+10.352 ms**。本批未出现此前约 30 ms 的整体上移，不能据五轮保证固定开销或零开销。

本次没有换版、重启服务或清缓存；三组使用同一份带 SID/warmup 导出的 cube-bench。当前 API/Master **没有可用的 frontdoor 入口观测**，因此此次抓取覆盖已有 Master/Host/组件阶段，Client→API、API→Master 继续明确标缺失，不用历史阶段或残差替代。

## 1. “合理值”如何判断

采集前记录的 [预先记录的计划](evidence/plan.json) 要求五轮各 100/100 成功、服务身份固定、库存与 TAP 清理通过、无冲突工作；整轮中位不超过 200 ms、所有轮次不超过 250 ms。后两项是根据历史约 129–198 ms 数量级设的**诊断筛选**，不是性能 SLA、统计等效或收益门槛。实际 B 五轮均在 124–145 ms 内。[决策记录](evidence/baseline-decision.json)

正式配置为 c100/n100/create-only、同进程串行 w3；预热排除在 `summary.total_time_s` 之外。模板 `template-A`（公开别名）、2000m/2048Mi、1G writable、XFS、探针 49999 `/health` 的 100 ms timeout / 500 ms period 沿用配置。内核实读 6.6.0，THP=madvise，NUMA balancing=0，每轮前后门禁记录 738 Ready/free TAP、空库存、未发现 VM/perf/编译/其他压测冲突，load1≤4；门禁不证明负载整个期间完全没有后台活动。

API/Master 从 14:17 左右持续运行到本批结束。**B 五轮后继续同一服务进程**，交错顺序为 F1→D1、D2→F2、F3→D3、D4→F4、F5→D5；每轮精确清理本轮 103 个 SID，等待 15 秒并通过门禁。没有新增预读、预 CoW、模板重建或服务切换。

所有组都有负载前后的身份检查和日志字节窗口；F 额外运行 `capture_100.sh` 完整采集/分析流程。负载由 Bash 直接启动 cube-bench，没有 Python 轮询器或代理夹在请求路径。该比较只衡量**既有日志采集流程**，不能外推到 API/Master frontdoor 打点或客户端 HTTP trace 的开销。
